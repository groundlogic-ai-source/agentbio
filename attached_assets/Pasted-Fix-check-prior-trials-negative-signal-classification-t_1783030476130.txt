Fix check_prior_trials' negative-signal classification to distinguish real
failure from administrative/regulatory termination.

For every TERMINATED, WITHDRAWN, or SUSPENDED trial found for a (drug,
disease) or (target, disease) pair, fetch protocolSection.statusModule.
whyStopped from the ClinicalTrials.gov v2 API response (already being
queried, this field is in the same response, just not currently read).

Classify has_negative_repurposing_result using this logic:
- If whyStopped is present and its text indicates efficacy/safety failure
  (e.g. contains language about lack of efficacy, safety concern, adverse
  events, futility, DSMB recommendation to stop) -> TRUE negative signal
- If whyStopped is present and indicates administrative/non-efficacy reasons
  (e.g. "post-marketing commitment fulfilled," "business decision,"
  "funding," "low enrollment," "sponsor decision," "study design changed")
  -> NOT a negative signal, exclude from the penalty
- If whyStopped is absent/empty -> treat as UNKNOWN, not as a negative
  signal by default (the current behavior silently assumes negative; that
  default is the actual bug)

Use one Haiku-tier LLM call per whyStopped text (short, cheap, constrained
classification: "does this termination reason indicate the treatment
failed on efficacy/safety, or was it for an unrelated administrative
reason? Answer only EFFICACY_FAILURE, ADMINISTRATIVE, or UNCLEAR") rather
than keyword matching, since termination reasons are free text and won't
match a fixed keyword list reliably. Pin temperature=0 on this call, same
as the other classification calls.

Store and surface the actual whyStopped text and classification in the
report evidence table when a trial history exists, not just a boolean --
this is important for auditability, don't hide the reasoning.

After the fix, rerun Pompe disease target selection and print GAA's full
score trace again (same format as the last diagnostic) to show whether the
trial penalty changes, and whether GAA now outranks UGCG. Also rerun the
full retrospective validation batch (sildenafil, thalidomide, everolimus)
since this same classification logic affects check_prior_trials calls used
elsewhere in reviewer.py, not just target_selection.py.
