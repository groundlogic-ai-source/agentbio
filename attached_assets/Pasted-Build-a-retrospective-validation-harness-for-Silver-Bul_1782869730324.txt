Build a retrospective validation harness for Silver Bullet — a separate module,
does not touch the live case pipeline. Purpose: test whether the existing
Biologist/Chemist/Reviewer scoring pipeline would surface a drug-disease pair
that is ALREADY a confirmed real-world repurposing success, run as if that
answer were unknown.

PART A — Ground truth set
Create validation/ground_truth.json with 5 entries, each:
{drug_name, disease_name, confirmed_year, source_note}. Use these confirmed,
well-documented repurposing cases:
1. Sildenafil - pulmonary arterial hypertension (originally developed for
   angina/hypertension)
2. Thalidomide - multiple myeloma
3. Metformin - polycystic ovary syndrome (PCOS)
4. Everolimus - tuberous sclerosis complex (TSC) related seizures/tumors
5. Propranolol - infantile hemangioma
Look up and confirm each pair's actual approval/discovery year before including
it — do not assume, verify via a real source (e.g. FDA approval records or a
review paper) and store the source_note.

PART B — Harness logic (validation/run_retrospective.py)
For each ground truth entry:
1. Run the SAME Biologist -> Chemist -> Reviewer pipeline already built,
   targeting disease_name, with NO knowledge of drug_name fed in anywhere —
   the pipeline must discover candidates independently exactly as it does for
   a normal blank/manual case.
2. Do NOT exclude the confirmed drug from ChEMBL/PubChem results — we are not
   simulating pre-approval data availability (that's not feasible with live
   current APIs), we are testing whether the SCORING AND RANKING LOGIC would
   surface the right answer among real candidates, not whether the raw data
   existed at that historical time. State this limitation explicitly in the
   output, don't obscure it.
3. Record: did the confirmed drug appear anywhere in the Chemist's ranked
   candidate list? At what rank? What was its composite_score? Did it reach
   STRONG_MATCH?

PART C — Report
Output validation/results.json and a human-readable results.md summarizing,
per case: hit/miss, rank if found, composite_score, and one honest sentence of
interpretation. Then an overall summary: X/5 confirmed pairs were recovered in
the top 10 candidates, Y/5 reached STRONG_MATCH. Do not spin a bad result —
if something is missed, say so plainly and note any visible reason why (e.g.
Tanimoto found no structural match, or ChEMBL confidence was too low).

This is read-only validation — do not modify chemist.py, reviewer.py, or any
scoring logic to make these cases pass. If the existing pipeline doesn't find
some of them, that is real information, report it as-is.
