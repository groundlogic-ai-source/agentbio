Building on the existing project (Stages 1-3 — do not modify their internal logic,
only import from main_graph.py and reuse resume_review.py's underlying resume
function rather than duplicating it), add a FastAPI backend that exposes the
existing LangGraph pipeline over HTTP. This project is called Silver Bullet. This
is a single-user hobby project — do NOT add user accounts, login, or any
authentication. Do NOT introduce Celery, Redis, or any external task queue —
background jobs run as simple Python threads.

PART A — Job tracking (api/jobs_db.py)
- Add a SQLite table called `jobs` (a separate file or separate table from the
  LangGraph checkpoints.db used for graph state — don't mix them) with columns:
  job_id, thread_id, disease_name, status (queued/running/awaiting_review/
  completed/error), current_stage (one of: target_selection/biologist/chemist/
  reviewer/structure_validation/writer/awaiting_review/done), created_at,
  updated_at, error_message, total_cost_usd.
- Functions: create_job(), update_job_status(job_id, **fields), get_job(job_id),
  list_jobs() (most recent first).

PART B — FastAPI app (api/main.py)
- Bind to host 0.0.0.0 and read the port from the PORT environment variable —
  Replit sets this, never hardcode a port.
- Endpoints:
  - POST /api/runs — body: {disease_name: optional string}. If omitted, the run
    starts from Stage 1's target selection and auto-picks the top-ranked
    candidate. Creates a job record, starts the LangGraph run on a background
    thread, and returns {job_id} immediately — must not block waiting for the
    run to finish.
  - GET /api/runs — returns list_jobs().
  - GET /api/runs/{job_id} — returns the full job record, plus the compiled
    report content if status is awaiting_review or completed.
  - POST /api/runs/{job_id}/resume — body: {action: "approve" or "reject",
    notes: optional string}. Looks up the job's thread_id and calls the graph's
    Command(resume=...) with the appropriate payload. This must call the exact
    same underlying function resume_review.py uses, not a reimplementation.
  - GET /api/runs/{job_id}/cost — returns total_cost_usd.
- The background thread must update the jobs table's current_stage as the graph
  actually progresses through each node (hook into LangGraph's stream/event
  output after each node completes) — current_stage has to reflect real
  progress, not just flip from "running" to "done."
- Add a catch-all static-file route that will serve a frontend build from
  /static once Stage 5 exists. For now just create an empty /static folder and
  the route — don't build any frontend yet.
- Add permissive CORS middleware for localhost origins so local frontend
  development isn't blocked later.
