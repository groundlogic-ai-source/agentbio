The Reviewer agent's composite scoring formula does not currently account for
whether a candidate is an approved/known drug, even though "approved_drug" is
already being fetched and displayed in the evidence table. This is a real gap:
this system is specifically for REPURPOSING, which requires the candidate
already have an established human safety profile from prior approval — an
unapproved research compound that merely binds the target is a fundamentally
different and much weaker kind of finding, not a repurposing candidate.

Fix:
1. In the composite_score formula, add a hard gate: if approved_drug is False,
   the candidate cannot reach STRONG_MATCH regardless of its other scores —
   cap the maximum composite_score at 0.4 in that case (below the 0.7
   threshold), rather than silently treating it as a normal candidate.
2. Add a clearly visible label change in both the evidence table and the
   report header for any candidate where approved_drug is False — e.g. a
   distinct badge like "EXPERIMENTAL COMPOUND — NOT YET APPROVED" instead of
   the normal STRONG_MATCH stamp, so this is impossible to miss even at a
   glance.
3. Audit the Chemist agent's candidate-generation step: it was supposed to be
   prioritizing approved/known drugs per the original design. Check why an
   unapproved compound (CHEMBL4855757) was generated as a top candidate at
   all — confirm whether the approved-drug filter exists there and is being
   applied correctly, or whether it's only checked downstream in Reviewer.
4. Re-run the Stage 1 sweep's output (once the current sweep finishes) through
   the full pipeline on 2-3 known cases and confirm approved_drug is now
   actually gating outcomes correctly, with at least one deliberately-unapproved
   test case showing the new experimental-compound badge instead of
   STRONG_MATCH.

Do not change anything else. Read existing scoring.py / reviewer.py code before
editing to confirm the exact variable names already in use.
