Building on the existing project (Stages 1 and 2 — do not modify their files), add
the final stage: structure validation, report writing, and orchestration.

PART A — Boltz API integration (data_sources/boltz_api.py)
- Use the official Boltz API at https://api.boltz.bio (read their current docs for
  exact endpoint paths and request/response schema — do not guess the schema)
- Requires BOLTZ_API_KEY from environment
- Function: predict_complex(protein_sequence, ligand_smiles) submits a co-folding
  job and returns {structure_confidence, binding_pose_confidence,
  predicted_affinity, pdb_or_cif_url}
- Function: predict_adme(smiles) calls their ADME endpoint and returns the Tier-1
  property summary (use this instead of relying solely on RDKit Lipinski flags
  from Stage 2 — if both are available, prefer Boltz's ADME numbers and note the
  RDKit numbers as a secondary check)
- BEFORE calling predict_complex for any candidate, first check afdb.py
  (get_structure_confidence) for the target — if AFDB already has a high-confidence
  structure and you only need affinity/pose for the SAME ligand-free target, that's
  fine to use as a free starting point, but if you need the protein-LIGAND complex
  specifically (which is what actually matters for a docking-equivalent answer),
  call Boltz regardless since AFDB doesn't include ligands.
- Log the cost: each predict_complex call should print/log its estimated cost so
  the user can track spend.
- Do NOT use AlphaFold Server / alphafoldserver.com anywhere in this codebase.

PART B — Writer Agent (agents/writer.py)
Input: Reviewer's STRONG_MATCH candidates (from Stage 2) + Boltz structure/affinity/
ADME results for each.
- Compile a Markdown report per candidate with these exact sections:
  1. Hypothesis summary (1 paragraph)
  2. Evidence table: ChEMBL affinity + confidence_score, Open Targets association
     score, Tanimoto structural similarity + reference drug, BioGRID network
     context, Boltz structure confidence + predicted affinity, Boltz ADME summary
  3. Full source citations: every PMID, ChEMBL activity ID, and ClinicalTrials.gov
     NCT number used, deduplicated
  4. Composite score breakdown (show the formula and every term's contribution)
  5. Limitations section — include ALL of: affinity vs efficacy (binding doesn't
     prove antagonism), ADME is approximated not measured, structure confidence
     caveats (cite the actual pLDDT/confidence numbers used), assay-type and
     species-matching caveats, absence-of-evidence bias (no ChEMBL record means
     untested, not non-binding), and that this is a repurposing hypothesis
     requiring wet-lab validation, not a finding.
- Save each report as /output/reports/{disease}_{drug}.md

PART C — Orchestration (main_graph.py)
Use LangGraph (current version — read the current docs for the interrupt() and
Command(resume=...) API, do not use the older interrupt_before pattern or assume
old syntax). Build a graph with nodes: target_selection -> biologist -> chemist ->
reviewer -> structure_validation -> writer -> human_review.

CRITICAL requirements for this graph:
- Use a checkpointer backed by SqliteSaver pointed at a real file on disk
  (e.g. checkpoints.db), NOT MemorySaver/InMemorySaver — the whole point is that
  this needs to survive a Replit restart.
- The human_review node should be the ONLY node that calls interrupt(). It should
  present the final compiled report and ask for approval/edit/reject. Do not place
  any API calls before the interrupt() call within that same node, since resuming
  re-executes the node from its start.
- Do not write a polling loop that waits on a file appearing — the run should
  cleanly stop at the interrupt and be resumed later via a separate explicit
  invocation with Command(resume=...), e.g. triggered by the user running
  `python resume_review.py <thread_id> approve` from the command line.
- Write resume_review.py as a small CLI script for exactly that purpose.

Update README.md with the full end-to-end run instructions, including how to
resume after the human_review pause.
