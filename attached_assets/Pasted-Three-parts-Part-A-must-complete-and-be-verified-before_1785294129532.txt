PART A — Audit / rank-comparison tool
=====================================================================

Build a new endpoint + UI view: given a disease name and a specific drug
name (user-submitted), report where that drug actually stands in
AgentBio's own reasoning for that disease.

1. Check whether a completed or awaiting-review case already exists for
   the exact queried disease. If yes, reuse its already-computed
   reviewed_candidates pool -- do not re-run the pipeline. If no, trigger
   a real case run through the existing pipeline (respecting the rate
   limiter) and use its output once complete.

2. Resolve the queried drug name using the EXISTING, already-fixed
   ChEMBL name-resolution function (best-match, not first-match, with
   salt-form/synonym handling) -- do not write a new resolution path.

3. Look up the resolved drug within the case's candidate pool:
   - If present: report its full rank, composite score, and complete
     score breakdown, displayed alongside AgentBio's own top-ranked
     candidate for direct comparison. If it was capped for ANY reason
     (DILI whole-pool precap, mechanism-direction incompatibility, the
     safety layer, an unapproved-compound cap), state which cap fired
     and why, reusing the exact same disclosure banners already built
     for case dossiers -- do not build a second, separate explanation
     path that could drift out of sync with the live reports.
   - If absent from the pool entirely: check whether the drug's real
     ChEMBL-documented mechanism target matches AgentBio's own top-
     selected target for this disease. If it targets a different
     protein, state plainly which target AgentBio selected, which
     target the queried drug actually acts on, and if that second
     target was itself scored anywhere in Stage 1's ranking for this
     disease (and at what rank), or was absent from Open Targets'
     association list entirely.

4. One grounded narration step (Claude Opus 4.8) explaining the numeric
   comparison in plain language -- strictly narrating already-computed
   numbers, never introducing a new claim.

5. Mandatory disclosure, always shown regardless of outcome: a low rank
   or absence from the pool does not mean the queried drug is a poor
   candidate -- it may reflect a gap in public bioactivity/association
   data, not a real biological judgment against it.

6. Add this as a clearly separate UI section, not folded into Case Files
   or Research -- this compares an external candidate against AgentBio's
   own reasoning, distinct from either existing tab.

VERIFY before moving to Part B: run this live against at least two real
cases -- one where a known drug should be absent from the pool (e.g.
thalidomide against multiple myeloma, expected to be absent or off-
target) and one where a drug should be present and rank favorably.
Show the actual tool output for both, not a description of expected
behavior.
