Four additions to the bisociation research module.

1. Add a post-confirmation "confound investigation" step: for each
   hypothesis that survives both discovery FDR correction and holdout
   confirmation, Claude Opus 4.8 (separate call from the pre-test lead
   review) proposes 1-3 specific, named confounding variables that could
   explain the correlation without the original hypothesis being real.
   For each proposed confound that is computable from the dataset or a
   simple enrichment, run a multivariate logistic regression including it
   as a covariate and report whether the original effect survives
   adjustment (odds ratio, CI, p-value with and without the confound).
   Report this as "candidate explanations checked," never as "the
   confirmed mechanism."

2. Add a sandboxed AgentBio investigation script, fully separate from the
   live API: calls target_selection/chemist/reviewer scoring functions
   directly in an isolated context. Never creates rows in the production
   jobs table or explored_targets. Its only output is a research note
   flagging specific interesting cases for human review -- explicitly
   labeled as anecdotal, never presented as statistical confirmation of
   any repoDB-derived finding, since AgentBio's candidate pool is a
   filtered, non-random population and cannot serve as an independent
   replication sample.

3. Add a "Research" tab to the UI, separate from Case Files, showing the
   hypothesis registry (tested, FDR pass/fail, confirmation pass/fail)
   with the same awaiting-review pattern as case dossiers. Include a
   "submit your own hypothesis" input that routes directly to the lead
   LLM's testing step, skipping the two generators, but writes to the
   exact same cumulative hypothesis log used for FDR correction -- no
   separate accounting path.

4. Lock methodology (test type, significance threshold, correction
   method) per hypothesis at submission time, before any result is
   computed. If a hypothesis is ever re-tested under different
   methodology, log it as a new, separate entry in the cumulative
   correction log, never overwrite or replace the original entry.
