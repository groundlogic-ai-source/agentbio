Three changes to the bisociative research pipeline.

1. GENERATION INSTRUCTIONS — encourage radical novelty explicitly

Update both generator prompts (LLM A: Claude Opus 4.8, LLM B: GPT-5.6 Sol)
and the Lead LLM's review prompt to state plainly: bold, surprising,
counter-intuitive, and high-risk hypotheses are explicitly desired, not
merely tolerated. The deterministic statistical pipeline (Fisher's exact
or logistic regression, Benjamini-Hochberg FDR correction, independent
holdout confirmation, confound adjustment) is solely responsible for
validity -- generation should never self-censor an idea for sounding
unlikely or unconventional. The only legitimate reasons to discard a
candidate at generation/review time are: it cannot be reduced to a real
computable statistic from the dataset, or it lacks a genuine one-sentence
mechanistic justification (a real causal/structural argument, not "this
sounds plausible"). Keep the existing instruction to avoid lazy, generic
cliche domains (bare "evolution," bare "market economics") unless a
genuinely sharp, specific, non-obvious angle is given -- that instruction
already pushes toward novelty, not away from it, and should stay.

Add one honest parsimony note, framed as a technical fact, not a
creativity constraint: since every hypothesis tested adds to the
cumulative FDR correction total, generators should favor a smaller number
of genuinely distinct, sharp ideas per domain over many near-duplicate
variations of the same underlying concept.

2. GENERALIZE THE TAUTOLOGY/LABEL-CONFOUNDING CHECK

The current is_confounded check only catches features matching a fixed
keyword list (prc_raw, prc_threshold) plus the specific refractory/
resistant-term patch. Generalize this into a standing structural
reasoning requirement in the Lead LLM's review step: for every candidate
hypothesis, explicitly reason about whether the proposed feature could be
definitionally or structurally entangled with how the outcome label
itself was constructed (the H21 lesson: "refractory" indications are
near-definitionally later-line, non-original approvals). This must be a
real reasoning check against the feature's actual relationship to label
construction, not a pattern-match against a fixed list of past bad
examples, since new tautological patterns will not resemble old ones.
Discard or flag any hypothesis failing this check, with the specific
reasoning shown in the report.

3. ADD WEB-SEARCH NOVELTY TAGGING (informational only, never gates testing)

Add one Lead LLM (Opus 4.8) call per candidate hypothesis, before testing,
with web search enabled: "Search whether the following relationship is
already established or textbook knowledge in pharmacology/drug
repurposing literature: [hypothesis text]. Cite sources." Tag the result
NOVEL / ALREADY_ESTABLISHED / UNCLEAR. This tag is metadata carried
through to the final report only -- it must NEVER block, deprioritize, or
otherwise gate whether a hypothesis proceeds through discovery,
confirmation, or confound-checking. An already-established finding still
has real value as a validation check of the pipeline's own correctness
and must be tested and reported the same as any other -- it should simply
never be presented as a novel finding, or proposed for a mode, without
that context stated plainly.

Run one new discovery batch after these changes and report whether the
resulting hypotheses look qualitatively bolder/more varied than prior
batches.
